# MG 运动第二课｜速度、空间和物理反馈（2026-10-08）

## 来源与可信度

来自克肆（Claude）《给洄光-第二课-让东西真的在飞》的局部重做，及娜娜酱对《一毫米》V1→V2→V3 的逐轮反馈。用**能力与方法**，不照抄具体航线、参数和造型。

**必须保留的不舒服的事实**：
- 《把时间交给风》原版飞机像平面箭头沿曲线滑动；克肆的示范版有明显进步，但娜娜酱仍认为「不太像真的飞机飞」。
- 《一毫米》整体受到认可；但 V1 连锁反应像匀速计时器，V2 把撞击间隔从固定13帧改成19→11帧，V3 加入球沿斜坡加速、碰后回弹与阻尼，娜娜酱最终评价为「好一些，但是不太多」。
- 不得宣称已获得真实刚体、空气动力学或高水准自然运动。**物理参数的存在不是观感证据。**

## 1. 从“在动”进阶到“为什么会这样动”

写代码前按镜头列清楚：
**驱动力**（重力、冲力、风、主动动作）、**物体属性**（质量/形状/阻力/支点）、**约束/接触**（坡道、下一块骨牌、轨道、地面）、**反馈**（回弹、振动、摩擦、形变、尘屑、音效）、**收尾**（停稳/落地/飞出/被接住）。

需要导演的速度设计不必是严格现实模拟，但至少：
- 启动需要加速或充分的外力解释。
- 撞击前后速度发生因果变化；物体没有穿透或莫名静止。
- 缓停有阻尼；硬停有接触、边界或主动控制。
- 弹回受弹性与摩擦制约；不应凭空出现多余的二次移动。
- 相关音效从**真实事件数据**驱动，不能只靠事后把几个音效“卡在差不多的位置”。

## 2. 飞行/自由运动：克肆第二课的九条工程教训

原文与示范源码（`flight.py`、`flight.json`、`index.jsx`、`soundtrack.py`）在作者本地，未随仓库公开；下表是其中可迁移的部分。

| 常见假运动 | 应检查的原因 | 可选技术方向 |
|---|---|---|
| 段与段之间突然刹停/加速 | 每段独立 ease、端点切线不连续 | 连续切线的路径、沿弧长重新采样；检测速度/方向跨段跳变 |
| 曲线参数匀速不等于空间速度匀速 | 贝塞尔参数与实际弧长不等价 | 建立弧长表、按 ds/v 积分求时间 |
| 贴纸在平面里转向 | 只有 rotate，没有俯仰、横滚、明暗 | 3D/2.5D 面片、转弯侧倾、近远遮挡、稳定光源 |
| 上下飞速度一样 | 无能量交换 | 高度/重力/升阻力影响速度（物理与导演双约束） |
| 空白背景没有速度感 | 参照系缺失 | 世界坐标固定的景物/风/纸纹、随镜头产生视差 |
| 飞行中的物体突然悬停 | 提前截断路径且没有阻力/降落事件 | 消失于画外、降落或符合剧情的受力停下 |
| 起飞一帧突然变大/方向跳变 | 状态切换导致不连续 | 折叠/缩放/旋转从前帧连续过渡；扫相邻帧 |
| 轨迹长时间固定 | 轨迹没有生命周期 | 随年龄衰减透明度/粗细、被风吹走 |
| 风线跟着飞机屁股跑 | 风放在对象局部坐标而不是世界 | 固定世界流场，飞机穿过风场；声像与速度联动 |

**注意**：克肆选用 centripetal Catmull-Rom、能量约束、横滚滞后及 2.5D 投影，是这部作品的解决方案，而非要求每种动画都用 Catmull-Rom 和同一个重力参数。

## 3. 《一毫米》V1→V2→V3：加速度不止一层

（源工程在作者本地，未随仓库公开。）

### V1：计时器式运动（反例）
- 单个骨牌角度序列考虑了加速度，但所有骨牌复制相同的倾倒过程；
- 下一块骨牌固定每13帧被触发，**传播**匀速；
- 小球碰后使用手写位移回退，没有关联入射速度与碰撞反馈。

### V2：传播加速（改进，未获满分）
- 让骨牌间距**递进收紧**（131px→75px，整体长度维持）；按每块物理倾倒的角度达到几何接触阈值来触发下一块；
- 继承一部分前一块碰撞时的角速度；
- 实际间隔：`[19,16,15,14,14,13,13,12,12,11,11,11]` 帧；首/尾加速约 1.73 倍；
- 音效从同一份 `motion-data.json` 读实际撞击帧；
- 注意：「越往后越近」是在这条影片中为视觉效果做的几何导演选择，不能拿它冒充真实多米诺连锁动力学定律。

### V3：小球物理反馈（再改进，娜娜酱仍仅觉小幅提升）
- 沿坡小球运动 `x=280+0.95 f+0.0545 f²`，速度从 0.95→约 11.6 像素/帧；
- 第99帧碰撞，撞击后一帧速度反向，恢复系数采用0.36的视觉近似；
- 反向约38px并通过指数阻尼减速；极短的法线方向小跳，回落贴住斜坡；
- 滚动颗粒声按约24像素移动距离出发，不再每固定4帧出一次；
- **真实问题仍需执行 Agent 独立寻找**：画面与受力的可信度、动效尺度、节奏、相机，以及碰撞发生点在透视/形状上是否真能说服人，而非仅数值对齐。

### 可复用判断
不是“所有动作都改成越来越快”，而是**谁在加速，谁在减速，为什么，什么时候交出能量**。碰撞前预期、撞击一瞬、反弹/形变、摩擦停稳、后续被撞对象启动要形成“一个事件”，不能每项各写一段互相无关的动画。

## 4. 输出帧共享数据与QA

工作建议：`motion-data.json`（每帧位置/速度/方向/角度/接触时间/相机）同时驱动画面与声音。
- 检查帧到帧的**位置、速度、加速度、航向、缩放、透明度**在关键事件前后有没有意外断点。
- 接触相邻帧放大看：接触前3帧、当帧、后1/3/6/12帧；碰撞判据来自物体真实边界（几何/物理空间）。
- 检查深度、遮挡、画面边缘、主体身份，留世界参照系和摄影机随动的空间感觉。
- 每0.5秒做拼图 + 快动作连拍；不能用0.5秒抽帧代替检查加速度和一帧突然跳动。
- 用户对“好不好看”的评价优先于脚本自评；结果不够好要记录，别机械宣称“所有测试通过所以很真实”。

## 5. 反模板化

不强制所有动画都加入物理模拟：图形文字、角色表演、卡通夸张、多米诺、3D产品各有不同的运动语言。先选择表达目标，再决定物理模拟程度；二次创作/剧情场景优先遵循用户已定人物设计、台词、构图和节奏。

当使用第三方仓库研究运动语言时，只做技术和思路的学习，明确独立原创与商用许可证边界。不要把非商业许可的完整 Skill/代码不经授权并入自己的工程。
