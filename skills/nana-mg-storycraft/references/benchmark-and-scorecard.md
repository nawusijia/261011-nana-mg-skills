# 跨 Agent MG 教学与评测方案（可复现）

## 目标

对比不同 Agent 在相同计算环境、时长、素材约束下，是否能把一个抽象题目转化为真正有表达的程序化动画。不可把“能出 MP4”当成“会做电影感 MG”。

## 评测设置

- 固定环境：同一台 Windows、同版本 Remotion/GSAP、同 FFmpeg、同素材库；分别在独立工程目录交付，禁止互相覆盖。
- 固定任务：同一主题、时长、画幅、音轨要求、允许工具、截止条件；统一给出完整 brief 与验收清单。
- 记录条件：模型准确名称、版本、入口、启动前可读 Skills、是否读到对方的案例、总调用与修改次数。否则不说这是“模型纯能力比较”。
- 教学对照：同一个 Agent 先做无 Skill 基线，再给本 Skill 做复作；反向测试一个**完全不同主题**，检查是否只是复制《AI 的诞生》。
- 可选盲评：用户不知道哪份是哪家模型时先评感受；看完再公开 Agent、工具与迭代次数。不能拿一次结果推断普遍排序。

## 交给 Agent 的标准任务模板

> 请独立创作一条 12–15 秒、1920x1080、30fps 的程序化 MG。主题：“[具体主题]”。用户受众：[受众]，期望情绪：[情绪]，限制：[品牌/素材/字体/配乐等]。可使用 [固定技术栈]。最终提交可播放的 H.264 MP4、音轨、可编辑工程、可复现步骤与审查记录。不得只写代码就结束；不得使用未授权现成音乐或借用别人的已完成动画。每个阶段输出项目内的简洁事件表和结果证据。

### 比较时的两轮

A. **基准轮**：不提供克肆案例或本 Skill，Agent 自由发挥。

B. **教学轮**：明确加载 nana-mg-storycraft/SKILL.md；按需加载相关 references，不暴露已成片的《AI 的诞生》具体剧情作为提示词，换主题测迁移。

## 评分标准（满分 100）

| 维度 | 权重 | 核心判据 |
|---|---:|---|
| 概念清晰与记忆点 | 25 | 观众能否不看解释理解“发生了什么” |
| 动作编排与对象连续性 | 20 | 是否有意义上的运动、精细节奏与跨状态连续 |
| 声画一体、配乐与空间 | 20 | 音色自然性、动静/和声/关键事件同步 |
| 构图、排版与色彩语义 | 15 | 是否清楚、克制或有意张扬、视觉有独特判断 |
| 情绪曲线与结尾落点 | 10 | 是否有期待/转折/情绪满足，不必统一燃炸 |
| 技术稳定与可复现 | 10 | 帧率、时长、音频、字体、黑帧、源文件齐全 |

评审区分三类：
- **客观机器项**（codec/fps/audio/黑帧/资源存在）可用脚本；
- **可见设计项**（字有没有乱、关键元素是否连续）需实拍帧/预览；
- **体验项**（好听、酷、感动）必须由用户判断，不要伪称机器指标已证明。

## 做成主题视频时的叙事结构

建议标题角度：「同样的电脑、同样的工具，为什么 Claude 的 MG 更像作品？我把它的导演方法做成了 Skill，再教给别的 Agent。」

内容只需 4 个拍点：
1. 先放两版成片做盲测（避免预置偏见）。
2. 公开“相同的对话入口 + 本地工作区 + Remotion + NumPy”，排除工具差异。
3. 拆解技能：一句话故事 → 共享声画事件表 → 连续形变 → 动态对比 → QA。
4. 给一个**全新主题**做二次验证（最好没有人物说“我”、文字汇聚等表面元素），让观众看到是否可迁移。

**关键警戒**：克肆提供的案例是教学来源，需恰当署名；Skill 在不同 Agent 上的有效性必须通过独立实跑验证，不要只展示 Skill 文件就宣布普遍提升。
