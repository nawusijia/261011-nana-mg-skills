# Nana MG Storycraft — 先讲清楚，再让它动

**公共 V1 · 2026-10-08。** 公开版维护在本仓库 `skills/nana-mg-storycraft/`。版本号表示方法包版本，不表示作品已获最终审美验收。迭代时保留旧稿，记录新反馈、具体修正和实际验证，再升版本。

## 使用范围与边界

本 Skill 是**导演决策层**，不是动画工具或固定风格模版。适合需要叙事、情绪、概念表达与声音设计的程序化 MG（通常 5–30 秒）。真正执行仍使用当前项目已有的 Remotion、HyperFrames/GSAP、AE 或其他合适工具；不要为使用本 Skill 额外启动框架或复制用户工程。若用户只要简单下三分之一、字幕、已指定动画或无配乐的视觉效果，保持任务最小化；不自动添加故事、音乐或特效。

本 Skill 的创作机制来自娜乌斯嘉工作室（NanaMotionLab）2026-10-08 的双版本对照，尤其是克肆（Claude）完成并获娜娜酱认可的《AI 的诞生》。**学习的是原则和决策，不是复制该片的故事、色板、字体或代码。** 当用户指定风格、品牌、旁白、时长、具体画面或音乐时，以用户要求为准。

## 0. 读取最小输入（不吃整套资料）

只读取必要的：主题/核心信息、受众、使用场景、时长和画幅、用户确认的风格与声音要求、可用素材、已有可复用镜头与工程规则。若有参考片，分析具体**事件、运动、声音与意义的关系**，不要只抄视觉表面。

**写一句话：这部短片里到底发生了什么可观察的变化？**
- 它必须包含「起始状态 → 触发事件 → 结束状态」，而不是“一个高科技/高级/酷炫的片子”。
- 如果一句话只能列出视觉效果（粒子、隧道、字母、卡片……），尚未有导演方案。
- 10–15 秒通常优先一条核心变化链，但不是硬性单镜头限制；产品介绍、教程、数据比较允许多事件。

**导演门禁 A：** 没有变化句、触发事件和观众最终应该理解/感受到的东西，不进入写动画代码阶段。

## 1. 设计单条变化链和事件表

先定义核心「连续对象/观念」：一个字、一段光、一条线、一个形状、一组数据、一个产品元素或一个角色隐喻。明确每个镜头它处于什么状态、上一步的元素怎样成为下一步的元素。

写项目本地简短事件表（建议 beat-map.md 或项目既有格式）：

| 时间或帧 | 观众看到的事件 | 哪个同一对象在改变 | 声音事件/空间 | 情绪与信息 | 稳定画面/阅读时间 |
|---|---|---|---|---|---|

所有人读同一张表：**导演、动效、声音、审片**。画面和音频都应取同一个时间常量/事件时间表，避免凭感觉互相猜时点。用户指定多个 Shot/场景时忠实保留，不强行压成一个。

**导演门禁 B：** 事件表必须包括起、触发、变化、落点；每一段存在是为了推故事，而不只是展示技术。

## 2. 设计视觉：对象身份、字体和颜色

- **连续性先于转场效果**：让对象发生材质、空间、形态、状态转换。遮罩/硬切可用，但必须有明确的叙事或节奏目的，不能因为懒于对齐几何而总用全屏色块盖。
- **同源数据几何**：要从粒子聚成文字/标记，预计算文字/图像轮廓、粒子终点，同一来源生成粒子态与实体态；字形字体、坐标和视觉尺度一致。具体实例见 references/geometry-and-motion.md。
- **文字是内容**：每一行文字问「遮住以后会少知道什么？」标题、数值、角色回应、UI 反馈才应该出现。伪科技编号、假时间码、随机英文等装饰默认不加；专业 UI 信息场景可以合理存在。
- **字体有身份**：不同角色、信息层级用字重、笔锋、字距、动态区分；优先可靠字体资源并确认实际渲染。不要强制全片统一宋体，也不要盲目使用系统默认字体。
- **配色有语义**：确定角色/信息的视觉层级，再为最重要的事件分配强调色；克制服务于概念。不是绝对只能一种彩色；当用户指定高饱和、多角色、多品牌色时，要有清晰的色彩职责。

**导演门禁 C：** 首帧、中段信息帧、落点帧必须各自有视觉层级，连续态的几何不跳、文字可读、没有无意义填充。

排版要检查实际字形边界，不能只比较文字baseline和元素中心。把标签、条形指示器、状态文案分成明确区域；镜头拉远后局部标注应重排或淡出，不能跟着主体挤到一起。详见 `references/polish-and-reveal.md`。

## 3. 运动像表演，不是循环 GIF

让缓慢、悬停、突然的加速度、停止都有因果。曲线与时差体现质量、意图、心理重量：
- 要让汇聚同时收束，可以按距离为不同粒子分配出发时刻：远点先动、近点后动；用弧线路径增加生物感，但根据当前故事决定轨迹，不强制全部使用弧线。
- 运动前可以留静默/停顿，真正的强动作通过对比被感知；但别为了“高级”硬塞静止。
- **真实运动类的重点门禁**：不仅问主体有没有加速度，还要问接触发生在哪里、碰后动量去哪里、是否回弹/摩擦/停稳、镜头/声效是否与受力事件一致；加公式不等于真实，详见 `references/motion-physics-and-feedback.md`。
- 避免每个对象一直独立 sin 漂移；每 0.5–1 秒应能指出清晰的状态变化或有意保留的情绪等待。
- 不能把“换四张互不相干的好看画面”等同于动画；跨场景记住动作动机与连续对象。

更多：references/geometry-and-motion.md。

**质感进阶：** 对称圆环绕轴旋转可能在画面上完全看不出来；使用有语义的亮段、轨道点、倾斜和视差使运动可见。弹性用于接收、接触或状态改变后的反馈，不给所有元素一直加弹跳。需要从局部揭示整体时，先建立同一个较大的世界，再用加速—快速展开—减速的镜头显示尺度；不是把小图缩小或突然换大图。具体曲线、逆时序和环的案例见 `references/polish-and-reveal.md`。

## 4. 声音与画面同剧本

若用户要求配乐/音效：
- 音乐结构从情绪变化而来，**不是默认套 120 BPM 鼓点**；有节奏、无节奏、半拍、空拍、停顿和和声解决都由剧情决定。
- 分清音效：事件点、环境底、氛围、上升/下沉、结束尾音。要求空间层次与动态，不是堆响。
- 关键事件由共享 event timing 驱动；可给同源视觉粒子事件配同源定位声音（时间/声像/强弱），防止声画脱节。
- 若合成声音：音色需有泛音差异、滤波、包络、声像、不同混响 send；预留尾音空间、峰值余量。数值验证不等于真实听感审查。
- **不假装听过**：可验音轨、波形、响度与节拍对位；若无法可靠试听，明确请用户做最终听感评审。
- 合成配乐先写调式/和弦与旋律音表，核对回应音、背景层、低音和有音高的SFX；不要用整数等差MIDI序列代替音乐设计。刻意不协和可以服务剧情，但要说明在哪个事件解决；响度合格不证明和声合理。具体失败与修正见 `references/case-study-iterations-v1.md`。

细节见 references/sound-as-story.md。

## 5. 验收与返工：先看成品而不是代码

**执行前必须读取 `references/visual-review-loop.md` 的实际视觉门禁。** 真正观看渲染截图/连帧、具体定位难看和错误、返工、按同一机位重渲对比，是**强制交付前动作**，不是建议。即使 `scripts/audit_mg.py` 显示全绿，也**不准**说画面过关。项目内 `visual-review.json` 要有真实观测；`python scripts/visual_gate.py --check <项目目录>` 只能检验**证据链有无**，永不返回主观美术评价。画面仍有问题必须继续改，不允许拿报告要求用户代替 Agent 审片。

1. 先 render 关键帧（含各事件前/后与转场边界），审构图、字号、同源轮廓、字号字体、可读性和溢出。
2. 再 render 低清全长样片，至少每 0.5 秒抽一帧成时间拼图，观察过度空白、重复微动、硬跳、不连贯转场。
3. 审声音：关键事件的声音定位；500ms RMS 起伏、峰值、混响尾音、音乐落点与故事起伏是否对应。允许有意不齐，不接受无意失配。
4. 修一次**能指出的**问题，再输出正式版；用 ffprobe 验证分辨率、帧率、时长、视频/音频流，检查黑帧、音频损坏、掉帧与结尾。建议执行 scripts/audit_mg.py；它仅能检查结构和数值，不能替代人工审美。
5. 交付成片、可编辑源、必要素材、必要复现命令、审查发现和无法主观验证事项。不得只写完 JSX/脚本就报完成。

**导演门禁 D：** 技术合格不等于作品合格。若不能用一句话解释观众看到的变化或镜头之间缺乏因果，不要宣称达到导演级成片。

- 用户要求具体编程时，再按相应工程里的 Remotion/HyperFrames 等技术 Skill 执行；本 Skill 不替代它们。
