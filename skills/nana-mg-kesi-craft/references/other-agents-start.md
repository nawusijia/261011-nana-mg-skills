# 给其他 Agent（Codex / Kimi / GLM 等）的最简启动方式

建议直接把下面这段话发给对应 Agent。无需让用户做技术验收，也无需把所有参考资料一次塞进上下文。

> 请打开本仓库的 skills/nana-mg-kesi-craft/SKILL.md。
> 按这份 Skill 操作；不要只给我一份策划书。
> 先执行 `python skills/nana-mg-kesi-craft/scripts/preflight.py`。
> 然后你自己为一个全新主题选择【SDF流体 / 3D软体阵列 / 2.5D等轴】之一，
> 只加载对应 reference。
> 在你的工作区里建立独立新工程，做原创10–15秒MG，包含：
> 一个明确的视觉转折、真实风格技术（不允许扁平圆球假流体/贴图假3D）、
> 与画面同源事件表驱动的原创音乐、静帧审查和至少一次有证据的返工。
> 输出有声音的MP4、可修改源码、cues.json、关键帧拼图、返工记录与环境清理记录。
> 不修改别人的原案例或全局工具链。
> 作品最后由我判断是否真正惊艳；不准把自动技术检查当成人工审美合格。
> 请直接执行，做好后汇报最终成果即可。

## 两阶段严格区分

A｜复现原课例：只在**独立副本**重渲其中一个老师案例，验证技术链（需要老师案例源码）。
B｜迁移能力考核：在**全新的设计概念、故事和画风**下重新制作；它才证明 Skill 能否教会别的 Agent 创作。

适合公平横评时记录：模型/版本、主题、环境、参考材料、Skill启用状态、真实迭代次数、完成时间、观众盲评。最好对同一 Agent 两次独立会话分别测「不用Skill」和「用Skill」，且两组都不看老师源码的成品视觉，以排除答案污染。

## 有老师案例源码时

案例的`make.sh`会**覆盖当前目录**的audio/video输出，所以不能在原案例文件夹直接重渲；验证A先用 `python skills/nana-mg-kesi-craft/scripts/prepare_case.py --cases-dir <案例目录> --case 3d --name 3d-study-copy`（三风格可切换）制作**隔离副本**，再进副本运行 `make.sh`。可用 `--node-modules` 链接已有依赖，避免重复安装；商用或公开发代码前核MIT声明和字体/HDRI/采样的独立授权。
